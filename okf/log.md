# OKF Change Log

## 2026-09-26

* **Added**: `kernel/dos/fsck.{c,h}`, `kernel/dos/fsck_fat32.c`, `kernel/shell/cmd_fsck.c` + `C:fsck` — feature-rich disk/filesystem interrogation and repair tool (UAOS-87). A generic `FsckCtx`/`FsckFS` probe-and-dispatch framework drives per-filesystem checkers; FAT32 is fully implemented (BPB validation with backup-boot restore, FSINFO check+rewrite, batched FAT1/FAT2 compare with resync, FAT entry scan, iterative directory walk with cross-link/loop detection and size-vs-chain reconciliation, clusterless-directory repair via free-cluster allocation, lost-cluster reclaim, free-space reconciliation). Whole-disk devices get MBR (bounds/boot-flag/overlap + rewrite), GPT (header CRC + usable range), and Amiga RDB (RDSK/PART/FSHD checksums) analysis with repairs; `SURFACE` runs a breakable batched media read test, `DUMP=n` hex-dumps a sector, `INFO` prints per-FS metadata. Interrogation-only handlers exist for FAT12/16, ext2/3/4 (dirty/error flags), FFS/OFS (bootblock checksum repair), PFS/SFS, exFAT, NTFS, ISO9660 — future checkers register one row in `k_fsck_fs[]`. Heavy FAT passes read in ≤64 KiB batches with retries (single reads tripped transient VirtIO failures on multi-GB volumes); `fixed` counts only apply on successful writeback. Modes: `CHECK` (default, read-only), `REPAIR`/`FIX`, `INTERACTIVE` (per-fix y/n), `LIST`, `ALL`, `VERBOSE`; `failat` codes 0/5/10/20. Verified live in QEMU over telnetd: `fsck DH0:` full 4.1M-cluster check clean, `fsck virtio0` MBR listing, `fsck CD0:` flagged a real protective-MBR overrun, `SURFACE` reported all sectors readable, `INTERACTIVE` prompted per fix, and repair-write failure on ATAPI reported correctly.

* **Fixed**: `kernel/net/telnetd.c` — concurrent telnet sessions (UAOS-53). The listener task used to run `pump_session()` inline, so `tcp_accept()` was never reached while a session was live and the advertised busy path was unreachable — extra clients completed the handshake onto a silently dead socket. Now each accepted socket is handed to its own `telnetd-session` pump task (`PumpCtx` table, `TCP_MAX_SOCKETS` entries, generation-stamped so pumps from a previous run exit on their own), up to `MAX_REMOTE_SHELLS` (4) sessions run in parallel, and a connection with no free slot gets a "no remote shell slots free" banner + clean close. `g_pump_count` (cli/sti-guarded `++`/`--`) lets `Telnetd_Stop()` drain pumps inside its 1 s deadline. Remote session handles are tokenized in `shell_win.c` (`remote_token` in the handle's high 16 bits, never 0): `RemoteIsDead`/`RemoteKill`/`RemoteFeed` decode the handle and refuse it once the slot is released or reopened, so a stale pump can never feed a different session that reused the slot. Verified live in QEMU over `hostfwd` telnet: 4 concurrent sessions all get prompts and run commands simultaneously, the 5th gets the busy banner, and `endcli` frees the slot for a replacement session.
* **Fixed**: `kernel/display/shell_win.{c,h}`, `kernel/irq/ps2kbd.{c,h}`, `kernel/net/telnetd.c` + consumers (`vim_win.c`, `ed_win.c`, `requester.c`, `intuition_lib.c`) — real remote interrupt handling (UAOS-50). Root cause: `SHELL_VKEY_UP` was `0x03` — identical to Ctrl-C/ETX — so a remote Ctrl-C recalled history and a follow-up Enter could re-execute the previous command; Telnet `IAC IP`/`IAC AO` were mapped to backspace. The virtual cursor-key codes moved to `KBD_VKEY_*` (0xF9–0xFE, canonical in `ps2kbd.h`, aliased as `SHELL_VKEY_*`) so control bytes reach consumers as data again. New break path: `0x03` (from keyboard, remote feed, or NVT `IP`/`AO`) sets the instance `break_req` flag and signals `SIGF_BREAKF`. The flag is one-shot: whoever sees it consumes it (`shell_take_break` also flushes the input ring so stale keys are not executed). Consume points: `inst_dispatch` entry, the script block runner, both `FOR` loops, `shell_read_key`/`shell_read_line`, and the `NativeCmdCtx.break_pending` callback (`wait`, `ping`, `more` honour it). Foreground child waits `Wait(SIGF_CHILD|SIGF_BREAKF)` and forward the signal to the child **without** consuming the flag — consuming there silently swallowed breaks that landed mid-wait and let `FOR` loops run on. A `dispatch_broken` marker propagates a consumed break upward so an enclosing loop/script that already passed its own check still stops (`***Break` prints once). At an idle prompt Ctrl-C cancels the input line (`^C` + fresh prompt) instead of recalling history. `exec_make_ctx` was zero-initialised (stack garbage could have crashed callbacks). Verified live: Ctrl-C during `FOR` prints `***Break` with no history recall, `IAC IP` breaks a running command, idle Ctrl-C gives `^C` + fresh prompt, `wait` aborts, and the session stays usable (two consecutive runs, 15/15 checks).
* **Added**: `kernel/chipset/chiptrace.{c,h}` + `C:chiptrace` — custom-chip/CIA access tracer (UAOS-68). `Chiptrace_Hit` is called from `chip_emu_write` and a `chip_emu_read` wrapper (impl renamed `chip_emu_read_impl`), so it catches M68k memory-callback accesses and page-fault-forwarded native accesses alike. Classes are selected with a bitmask (`CT_CHIP`/`CT_CIA`/`CT_PAULA`/`CT_DISK`); a static+computed register-name table decodes addresses to names (`W DFF180 COLOR00 = 0xf0f`, `R BFD200 CIA-B.DDRA -> 0x55`), consecutive identical (op,offset,value) accesses fold into `xN` lines, and output is capped at 400 lines/s (over-cap counted as `dropped`). Guest M68k PC is attached when `Task_Current()->type == TASK_TYPE_M68K`. `chiptrace pc [N]` enables sampled M68k disassembly — `Chiptrace_PcSample()` runs after each `m68k_execute()` slice (exec_task.c, dos_lib.c, uaos_m68k_glue.c) and calls Musashi's `m68k_disassemble` at most once per N PIT ticks. `m68kdasm.c` is now compiled into the kernel and the build's stubs.c provides real `sprintf`/`strcat`/`strcpy`/`qsort` for it. New demo `system/Demos/ChipPoke.s` pokes one register per class for end-to-end verification. Verified in QEMU: all classes traced with `pc=` annotations, CIA-only filter emitted only CIA lines, PC sampling streamed `PC 00114A jsr (-$180,A6)` without wedging. (UAOS-68)

* **Fixed**: `kernel/net/tcp.c` — TCP send path hardened. `tcp_send` now enforces the peer's `snd_wnd` and returns 0 while a seq-carrying segment is still unacked (single-segment in-flight cap, so `retx_buf` always holds the segment needing replay — bursts can no longer strand holes). `snd_una` advances only on ACKs inside `(snd_una, snd_nxt]` (stale/reordered and out-of-range ACKs ignored; window still taken from any ACK). Segments matching no socket get an RFC 793 RST (`tcp_send_reset`; `tcp_rx` gained a `dst_ip` param so only segments addressed to us are answered). `tcp_close` defers its FIN (`fin_pending`) while data is unacked so it can't clobber the outstanding segment's retx state — `tcp_tick` releases it. Callers updated: telnetd `send_neg` retries briefly (greeting negotiation was being dropped), `remote_send`/`bsd_send` poll-and-retry with ~60 s stall bounds. Verified with a host-side harness (handshake, busy/send-window clamps, stale/out-of-range ACK rejection, deferred FIN, retx replay, RST cases — 30 checks). (UAOS-55)
* **Fixed**: `kernel/net/tcp.c` — RX ring overflow no longer corrupts the stream. `tcp_send_seg` advertised a constant 4095 window regardless of free space, and a full ring silently dropped segment tails while `rcv_nxt` still ACKed them. Now the window field tracks real `rbuf_free` space (0-window when full), `rcv_nxt` advances only by bytes actually queued (drop-and-NACK so retransmit recovers), retransmit overlap is trimmed and out-of-order segments dup-ACKed (`tcp_rx_data`), a FIN only counts once preceding data is delivered, data is accepted in the half-close states (`FIN_WAIT_1/2`, `CLOSE_WAIT`), and `tcp_recv` pushes a window-update ACK when a full ring drains. Verified with a host-side harness driving the state machine through overflow/partial-queue/retransmit/out-of-order/FIN races (30 checks). (UAOS-56)

## 2026-09-24

* **Fixed**: post-format `makedir` failure on a mounted FAT32 partition — `format Device=DH0: Name=wb fat32` previously tried to mount by the FAT label `wb`, which cannot resolve to a block device, while the existing DH0 handler retained pre-format cached geometry. Added `VFS_RemountPartition()` and changed both native format command paths to refresh/remount under the stable device display name (`DH0`); `Name=` now remains solely the disk label. Runtime confirmed the remount (`Mounted as DH0:`), exposing a second return-value bug: FAT `ACTION_CREATE_DIR` returns a positive lock handle, but `VFS_MkDir` accepted only `DOSTRUE`, falsely reporting failure and leaking the lock after successful creation. VFS now accepts the lock, frees it with `ACTION_FREE_LOCK`, and returns success. Runtime then showed long pauses and non-persistent directory entries: VirtIO-SCSI sampled the command queue's `used_idx` after notify, so VirtualBox could complete a small request before the wait began; the waiter captured the completed index and timed out waiting for the next one, while retries consumed mismatched completions. Completion now compares against an independent last-consumed used-index shadow initialized with the queue. Runtime then confirmed timing was fixed but directory entries were still not visible. `fat32_write_dir_entry` now verifies the exact 32-byte entry by immediate readback and retries 3x; the FAT handler no longer reports success if the newly created path cannot be reopened. Directory creation and reopen then passed but `dir` enumeration stayed empty. The native x86-64 `DosPacket` ABI stored `dp_Arg1`–`dp_Arg7` and `DoPkt` arguments as `int32_t`, and VFS/dos.library explicitly truncated 30 native path, buffer, and `FileInfoBlock` pointers. Packet arguments now use `intptr_t`, with all truncating casts removed; action codes, results, handles, and M68k-visible values remain 32-bit. Widening packet arguments did not fix FAT enumeration, so `VFS_ReadDir` now uses a direct `FatHandler_ReadDir` path (open, `FAT32_ReadDir`, close) for FAT handlers while retaining generic packet EXAMINE enumeration for other handlers. Runtime proved persistence because a second mkdir of the same name correctly failed as already existing, while `dir` remained empty. The direct FAT enumeration wrapper's 4.5KB temporary stack arrays were removed; `VfsDirEnt` is now a shared named structure and `FatHandler_ReadDir` fills the caller's array directly. Entries still persisted while listing stayed empty; `cmd_dir.c` itself allocated 256 `VfsDirEnt` records (about 18KB) on the command stack, overflowing/corrupting the kernel task stack when enumeration wrote results. The directory workspace now uses static storage. The actual shell command was then traced: migrated userspace `C:dir` calls `uaos_opendir/readdir`, while kernel `sys_opendir` was RAMFS-only (`VFS_ResolveDir` + `RamFsNode*`) and could never enumerate handler-backed FAT volumes. Syscall directory handles now support RAMFS node iteration and cached generic `VfsDirEnt` results from `VFS_ReadDir`; `sys_readdir` marshals either source to `UaosUserDirent`. Full ISO build succeeds; final VirtualBox confirmation pending. (UAOS-41)
