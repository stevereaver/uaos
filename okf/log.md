* **Changed**: the x86-64 userspace heap in `kernel/exec/elf64_loader.c` is no longer a bump arena — it is a boundary-tag free-list allocator (UAOS-152). The 4 MiB static arena is a doubly-linked chain of blocks ordered by address, each with a 48-byte header (`magic`, `size`, physical `prev`/`next`, `owner` task, `flags`) sitting immediately before its payload. First-fit alloc splits free blocks (lead split for alignment, tail split for the remainder); free clears the used bit and coalesces with free neighbours in O(1) since links are physical adjacency. Header-room edge cases: a lead sliver under 48 B is absorbed into the preceding used block (or orphaned at the arena base) rather than corrupting the chain; `x64_heap_reserve` — used by ET_EXEC images whose absolute vaddrs must land in-arena — refuses a range whose free block starts within 48 B of the image so the memcpy cannot clobber the header. All list mutation runs under the pushfq/cli critical-section idiom so a PIT preemption never sees a half-split chain.

## 2026-09-25

* **Fixed**: `kernel/drivers/virtio_net.c` — `virtio_net_send()` waited on `g_txq_last_used != g_txq_used->idx` before overwriting the shared TX buffer, an inverted condition that can never clear once the device posts TX used entries. QEMU never posts them so the wait was a no-op; VirtualBox does, so every send after the first spun the full bound with IRQs disabled and the system froze (telnet connect hard-locked the VM). Now waits on the real outstanding count (`avail->idx - used->idx != 0`) and latches `g_tx_no_used` after one progress-free timeout so QEMU keeps the old fast path. Also: `virtio_net_poll()` only rings the RX doorbell when RX descriptors were actually re-added (doorbell = VM exit; callers poll in tight loops). (UAOS-46)

(UAOS-54)
* **Fixed**: `kernel/net/telnetd.c` — session teardown after `netstop` no longer transmits: the pump calls the new `tcp_abort()` when `net_stack_is_up()` is false, since a FIN could never be answered and `tcp_tick` stops running while the stack is down (a graceful `tcp_close()` would leak the slot in `FIN_WAIT_1`).  `tcp_abort()` added to `kernel/net/tcp.c`/`tcp.h`. * **Fixed**: `kernel/net/tcp.c` / `tcp.h` — `tcp_accept()` no longer re-hands-out a socket it already claimed.
